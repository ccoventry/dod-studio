# Command Tiers: what Initial and Scheduled Commands may contain

A command a user types into Initial or Scheduled Commands falls into one of five lists in `native/src/patch/cfg_scan.rs`. **That file is the source of truth.** This page explains *why* each list exists; it names example members only to illustrate, and the set has been re-tiered more than once (`mirv_movie_filename` moved in #161; `mirv_movie_separate_hud` disappeared with #214). Read `cfg_scan.rs` before describing the current set.

Enforcement runs twice, independently: in `map_manager::scan_game_configs`'s report, and again in `capture_manager::start_capture_batch_impl`. The Commands type-ahead (`studio/src/command_suggest.js`) mirrors the tiers, so a tier change must be mirrored there too.

## The five lists

- **`BANNED_COMMANDS`** — refused **everywhere**, Initial and Scheduled alike. Two different reasons land a command here:
  - *The pipeline owns it outright* (`mirv_recordmovie_start`/`_stop`, `mirv_movie_ffmpeg`, `host_framerate`, `r_norefresh`). No setting corresponds to any of them, and a user's own value misroutes footage or desyncs playback with no visible failure. `r_norefresh` is the fast-forward's "draw nothing" switch (#724): `sys_fast_forward` sets it and every pre-roll clears it, so a user's `1` is either undone before any clip records or, scheduled inside a clip, records frames with no world in them.
  - *The hook DLL's batch runners* (`ds_capture_batch`, `ds_capture_schedule`, #434). One started from a batch's own commands would replace the batch that is running.
  - *DoD's client quits the game over it* (`r_drawentities`, `cl_lw`). `CHud::Redraw` forces the value back, prints an error and calls `quit` if either is not `1` (binary-level evidence: `docs/goldsrc_client_dll_internals.md` §5).

  Reachability differs between those two, and `FATAL_CVARS` encodes it: `cl_lw` always takes the value it is given, whereas GoldSrc itself clamps `r_drawentities` back to `1.0` while `sv_cheats` is `0`, making a config line setting it inert. Both stay refused as *typed commands* — cheap, and `cfg_scan` cannot see what else a user's configs did — but only `cl_lw` is reported as a fatal config cvar unconditionally.
- **`SCHEDULED_BANNED_COMMANDS`** — fine at demo load, refused **only when scheduled** (`r_decals`, `mirv_fov`, `gl_widescreenfov`, `mirv_movie_filename`, `mirv_agr`). Why `r_decals` must be set exactly once: `docs/goldsrc_dod_quirks.md`.
- **`MID_DEMO_HAZARDS`** — shadowed with a warning, not refused, because each corresponds to a real setting. `mid_demo_hazards` also reports **`FAST_FORWARD_CVARS`** (`fps_override`, `fps_max`, `gl_vsync`), which is not a tier of its own: `sys_fast_forward` sets them to run the gaps between clips uncapped (`builder/speed.rs`, #724) and `sys_normal_speed` puts back the value Initial Commands, then the game's executed configs, then the engine default state, at every pre-roll. In Initial Commands they are honoured exactly, so nothing is reported there; scheduled, one lasts only until the next clip's pre-roll, which is what the warning says.
- **The demo command filter** (`DEMO_FILTER_*`, `demo_filter_rule`) — reported as doing nothing, in Initial and Scheduled Commands alike, **only while Seek Between Clips (Pipeline tab) is off** (#679). Every type-3 `ConsoleCommand` frame goes through the same filter as `svc_stufftext` before it reaches the command buffer (`docs/goldsrc_hw_dll_survey.md` §13.3), and a patched batch writes both lists into the demo as those frames (`engine.rs`: Initial Commands right after `DemoStart`, Scheduled Commands at their frame). A Seek Between Clips batch does not: `runtime_batch.rs` writes them into the hook's batch file (`init` and `at` lines) and goldsrc-hooks `batch.rs` runs each through `ClientCmd`, which the filter never sees, so `exec movie.cfg`, `alias` and the rest run there. `scan_game_configs` takes the setting (`hook_runs_batch`) and leaves `filtered_init`/`filtered_scheduled` empty while it is on; the type-ahead's `tierNote` takes it as `seeks`. A Seek Between Clips batch that can't seek (no hook DLL, no demo-player times, and so on) is patched instead, and then the filter does apply: the activity log lists what it drops at that moment (`messages::dropped_when_patched`). The filter drops, with nothing printed:
  - any command whose **name contains** `bind`, `_set`, `unbind`, `retry`, `quit`, `_restart`, `motd_write`, `motdfile`, `kill`, `exit`, `writecfg`, `cl_filterstuffcmd` or `unbindall`, case-insensitively, or **starts with** `connect`. It is a substring test: HLAE's `mirv_matte_setcolor` is dropped for `_set`;
  - any line that **starts with** `alias `, or **contains** `exec` (only `tfc` is exempt, not DoD), `exit`, `_restart`, `writecfg`, `bind ` and a few more, or has a **word starting with** `kill`, `quit`, `_set`, `retry` or `connect `. Arguments count, so `echo got a kill` is dropped too.

  `exec` and `quit` used to have this tier to themselves, as `NOOP_EVERYWHERE_COMMANDS`, before the whole filter was read out of `hw.dll`. A config the engine execs at start-up is not filtered, so configs are not checked against it. Launch Preview and Launch Game run neither list (both start from `PatcherConfig::default()`'s empty `init_commands`, and the preview's patched copy carries only bookmarks), and the Launch Preview tooltip and the Initial Commands info say so. #434 moving the whole schedule into the hook would make this tier moot. The rules were read offline (pre-Anniversary in full, Anniversary rechecked); `native/examples/stufftext_probe.rs` writes a demo for the in-game check. Only the name stage is known to be case-insensitive; `cfg_scan` matches the line stage case-insensitively too, preferring a spare warning to a missed one. The stage that runs only when `cl_filterstuffcmd` is non-zero (default `0`) is not modelled.
- **`NOOP_IN_INIT_COMMANDS`** (`mirv_movie_filename`, `ds_capture_run_in_background`, `ds_capture_stay_behind`) — reported as doing nothing: the pipeline overwrites it before anything reads it (every batch turns `ds_capture_run_in_background` on, and sets `ds_capture_stay_behind` from Configuration > Pipeline's Keep the Game Behind Your Windows While Capturing checkbox).

## Adding a pipeline-internal command

If Initial or Scheduled Commands could reach a new command the pipeline relies on, decide which list it belongs to before shipping it unprotected, and mirror the choice in `command_suggest.js`. A command or alias the pipeline itself writes into a demo must also get past the demo filter: no `_set`, `kill`, `exit` and so on in its name. `builder/tests.rs` checks every one a batch writes.

## User config files

The game's own `.cfg` files are the user's: **detect and warn, never write.** A `config.cfg` ending in `exec movie.cfg` can set `mirv_fov` or `r_decals` behind the pipeline entirely, which is why `cfg_scan` also reads the user's configs. It is read-only by construction; keep it that way.

An Initial Command `exec <file>` that gets past the filter (Seek Between Clips on) is followed into its file too (`cfg_scan::follow_initial_exec`): the file is looked for the way the game's `Cmd_Exec_f` looks, `<game>` first (the `GAMECONFIG` path ID), then `<game>_addon` (`GAME`; Studio always launches with `-addons`), then `<game>_downloads` (any path) (`exec_search_dirs`), after the game's own name checks: only a `.cfg` or `.rc` name runs, no extension is added, and a name with a backslash, `:`, `~`, `..`, a leading `/` or more than one `.` is refused, and the files it execs in turn are followed the same way, under the start-up scan's depth, file-count and size bounds, each file read once so an exec loop ends. Its settings join the value rules at the place of the `exec` (`ValueSource::Exec`, shown as "<file>, line N, run by Initial Commands"). Like config lines, they count as the user's own files: a conflict made only of config and exec'd-file lines is not reported, but one with an Initial, app or Scheduled value is. An `exec` the game refuses or whose file is in none of those folders is reported (`missing_exec`): the game prints an error ("couldn't exec", "not a .cfg or .rc file", ...) and runs nothing.
